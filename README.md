# 🎓 Student AI — Early Warning System

> Predicts which students are at risk of failing **4 weeks before it happens** — then tells instructors exactly what to do about it.

---

## 🚩 The Problem

Universities lose millions to dropouts every year. Traditional systems flag students **after** they fail. This system predicts risk weeks in advance so instructors can intervene early, before it's too late.

---

## ⚙️ How It Works

1. Student activity is logged automatically — logins, forum posts, video watches, assignment submissions
2. XGBoost model scores each student **0–100** (risk score) using 14 behavioral features
3. SHAP explains **WHY**: *"missed 3 assignments, login count dropped 80%"*
4. Groq API generates a specific, actionable recommendation: *"Schedule a 1-on-1 check-in"*
5. Instructor sees this on the dashboard and acts
6. Student can view their own risk score and progress on their personal portal

## 🧠 The ML Pipeline

### Training Data
- 10,000 synthetic students generated by `generate_data.py`
- Each student has 10 weeks of engagement data + 3 assessment scores
- At-risk label computed from: low logins + low scores + missed assignments

### Features (14 total)
```
avg_logins, avg_forum_posts, avg_video_minutes, avg_submissions,
total_logins, login_trend, avg_score, min_score,
missed_assignments, submission_rate,
gender_enc, disability_enc, age_enc, edu_enc
```

### Model
- **XGBoost** — 100 trees, max depth 4, handles class imbalance automatically
- **AUC-ROC: 1.0** on synthetic data
- **SHAP** explainer generates top 3 risk factors per student
- **MLflow** tracks all experiments and model versions

### Full Prediction Flow
```
Student data in PostgreSQL
        ↓
Node.js API fetches 14 features
        ↓
POST http://ml-service:8000/predict
        ↓
XGBoost → risk_score (0-1)
SHAP   → top 3 factors
        ↓
Groq API → actionable suggestion
        ↓
Saved to risk_scores table
        ↓
Returned to instructor dashboard
        
Total time: ~200ms
```

## 🔄 Activity Tracking (Auto)

Every student action automatically updates their engagement data in PostgreSQL, which feeds into the ML model:

| Action | What gets tracked |
|---|---|
| Student logs in | `login_count + 1` |
| Student creates forum post | `forum_posts + 1` |
| Student replies to post | `forum_posts + 1` |
| Student marks video watched | `video_watch_minutes + duration` |
| Student submits assignment | `assignment_submissions + 1` + score saved |

## 🔑 Key Design Decisions

**XGBoost over Neural Networks** — Works great on tabular data, no GPU needed, much faster inference (~200ms), easier to explain with SHAP.

**SHAP for Explainability** — Raw risk scores aren't actionable. SHAP tells instructors the exact 3 reasons a student is flagged, making the system trustworthy and useful.

**Groq for LLM inference** — Groq's hardware accelerator delivers LLM responses in milliseconds, keeping the dashboard fast.

**Redis caching** — Predictions are cached for 1 hour so repeated requests don't re-run the ML model.

**Synthetic data** — OULAD dataset was unavailable, so 10,000 realistic students were generated with the same feature structure. Easy to swap in real data.

**Separate student portal** — Students interact with the platform (forum, videos, assignments), generating real engagement data that feeds back into the ML model.
